# ارزلرن (Arzlearn) — بک‌اند (فاز ۱ + فاز ۲)

## فاز ۱ — مدل‌ها و ادمین
- **accounts**: `CustomUser` با اعتبارسنجی نام کاربری انگلیسی و رمز عبور پیچیده.
- **articles**: `Category` (مادر/فرزند)، `Tag`، `Article` (CKEditor5، ۳ تگ اصلی اجباری، محاسبه خودکار زمان مطالعه).
- **comments**: `Comment` مرتبط به مقاله و کاربر.
- **prices**: `Price` + `services.py` (اسکرپر نوبیتکس/tgju) + دستور مدیریتی `update_prices`.
- **socials**: `SocialLink` برای فوتر.

## فاز ۲ — لایه API (Django REST Framework)

احراز هویت با **Token Authentication** انجام می‌شود. بعد از ثبت‌نام/ورود موفق یک `token`
دریافت می‌کنید که باید در هدر درخواست‌های بعدی ارسال شود:
```
Authorization: Token <token>
```

### accounts (`/api/accounts/`)
| متد | مسیر | توضیح |
|---|---|---|
| POST | `register/` | ثبت‌نام: `username`, `email`, `password`, `password_confirm` |
| POST | `login/` | ورود: `identifier` (نام‌کاربری یا ایمیل), `password` |
| POST | `logout/` | خروج (نیاز به توکن) |
| GET | `me/` | اطلاعات کاربر لاگین‌کرده (نیاز به توکن) — برای نمایش نام کاربری در هدر |

### articles (`/api/articles/`)
| متد | مسیر | توضیح |
|---|---|---|
| GET | `categories/` | درخت دسته‌بندی‌ها (مادر + فرزند) برای منوی هدر |
| GET | `categories/<slug>/` | لیست مقالات یک دسته‌بندی (صفحه اختصاصی دسته‌بندی) |
| GET | `latest-news/` | ۳ آخرین مقاله دسته‌بندی «اخبار» (سکشن هیرو صفحه اصلی) |
| GET | `latest-analysis/` | ۴ آخرین مقاله دسته‌بندی «تحلیل» (سکشن آخرین تحلیل‌ها) |
| GET | `search/?q=...` | جستجو در تایتل و متن مقالات |
| GET | `<slug>/` | جزئیات کامل یک مقاله + مطالب مشابه (بر اساس ۳ تگ اصلی) |

> ⚠️ سکشن‌های «آخرین اخبار» و «آخرین تحلیل‌ها» بر اساس نام دقیق دسته‌بندی («اخبار» و «تحلیل») که در ادمین جنگو ساخته می‌شود کار می‌کنند. این دو نام را دقیقاً همینطور در ادمین بسازید (یا در `articles/views.py` مقدار `NEWS_CATEGORY_NAME` / `ANALYSIS_CATEGORY_NAME` را تغییر دهید).

### comments (`/api/comments/`)
| متد | مسیر | توضیح |
|---|---|---|
| GET | `?article=<slug>` | لیست دیدگاه‌های یک مقاله |
| POST | (نیاز به توکن) | ثبت دیدگاه: `article` (id), `body`, `parent` (اختیاری) |

### prices (`/api/prices/`)
| متد | مسیر | توضیح |
|---|---|---|
| GET | `` | قیمت لحظه‌ای بیت‌کوین، اتریوم، سولانا، تتر، طلای ۱۸ عیار |

فرانت‌اند برای نمایش لحظه‌به‌لحظه، این endpoint را هر ۱ ثانیه poll می‌کند (در فاز ۴ با WebSocket جایگزین می‌شود).

### socials (`/api/socials/`)
| متد | مسیر | توضیح |
|---|---|---|
| GET | `` | آیتم‌های شبکه‌های اجتماعی فوتر |

## راه‌اندازی

```bash
python -m venv venv
source venv/bin/activate   # ویندوز: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# مقادیر دیتابیس PostgreSQL را در .env وارد کنید

python manage.py makemigrations
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

پنل ادمین: `http://127.0.0.1:8000/admin/`
API: `http://127.0.0.1:8000/api/...`

## گام بعدی (فاز ۳)
فرانت‌اند React + TypeScript: هدر/فوتر مشترک، صفحه اصلی، صفحه دسته‌بندی، صفحه مقاله، فرم ورود/ثبت‌نام.

## فاز ۴ — قیمت لحظه‌ای با WebSocket (Django Channels)

بجای Polling هر ۱ ثانیه، قیمت‌ها حالا از طریق WebSocket بصورت لحظه‌ای push می‌شوند.

### پیش‌نیاز: Redis

Channel Layer از Redis استفاده می‌کند (چون دستور `update_prices` در یک پراسس جدا از سرور اصلی اجرا می‌شود و باید پیام از طریق یک broker مشترک بین دو پراسس رد و بدل شود).

```bash
# نصب و اجرای Redis (روی اوبونتو/دبیان)
sudo apt install redis-server
redis-server
```

مقادیر `REDIS_HOST` و `REDIS_PORT` در `.env` قابل تنظیم هستند (پیش‌فرض: `127.0.0.1:6379`).

### اجرا

از آنجا که `daphne` به `INSTALLED_APPS` اضافه شده، همان دستور همیشگی هم HTTP و هم WebSocket را پوشش می‌دهد:

```bash
python manage.py runserver
```

و در ترمینال جدا، همان دستور فاز ۱ (که حالا علاوه بر ذخیره در دیتابیس، بلافاصله از طریق WebSocket هم پخش می‌کند):

```bash
python manage.py update_prices
```

### آدرس WebSocket

```
ws://127.0.0.1:8000/ws/prices/
```

فرمت پیام‌های دریافتی:

```json
// در لحظه اتصال (اسنپ‌شات کامل)
{ "type": "snapshot", "prices": [ { "symbol": "BTC", "name_fa": "بیت کوین", "price_value": "...", ... }, ... ] }

// بعد از هر بروزرسانی
{ "type": "update", "prices": [ ... ] }
```

> ⚠️ برای دیپلوی روی سرور واقعی (پروداکشن)، بجای `runserver` از `daphne arzlearn.asgi:application` پشت Nginx استفاده کنید و Redis را هم بصورت سرویس دائمی (systemd) اجرا کنید.

## فاز ۵ — سئو، اتوماسیون تلگرام، تقویم اقتصادی

### سئو
- **Sitemap پویا**: `http://127.0.0.1:8000/sitemap.xml` (شامل همه‌ی مقالات و دسته‌بندی‌ها، با لینک به آدرس فرانت‌اند).
- **robots.txt**: در `arzlearn_frontend/public/robots.txt` قرار دارد و به sitemap اشاره می‌کند. بعد از دیپلوی، آدرس واقعی بک‌اند را در آن جایگزین کنید.
- **Schema.org (JSON-LD)**: در فرانت‌اند تزریق می‌شود (Organization/WebSite در صفحه اصلی، Article + BreadcrumbList در صفحه مقاله، BreadcrumbList در صفحه دسته‌بندی).
- تنظیمات جدید در `.env`: `FRONTEND_BASE_URL`، `BACKEND_BASE_URL` (برای ساخت لینک‌های کامل در sitemap/schema/تلگرام؛ حتماً بعد از دیپلوی به آدرس واقعی سایت تغییر دهید).

### اتوماسیون پست تلگرام
هر مقاله‌ای که وضعیتش «منتشر شده» شود (چه موقع ساخت، چه بعداً از پیش‌نویس)، خودکار در کانال تلگرام پست می‌شود (عکس + عنوان + خلاصه + دکمه‌ی «ادامه مطلب»).

راه‌اندازی:
1. یک بات تلگرام از [@BotFather](https://t.me/BotFather) بسازید و توکنش را بگیرید.
2. بات را به‌عنوان **ادمین** کانالتان اضافه کنید (وگرنه اجازه‌ی پست کردن ندارد).
3. در `.env`:
   ```
   TELEGRAM_BOT_TOKEN=توکن-بات-شما
   TELEGRAM_CHANNEL_ID=@نام‌کاربری‌کانال
   ```
4. سرور را ری‌استارت کنید. از این به بعد هر مقاله‌ی منتشرشده خودکار پست می‌شود.

> ⚠️ توکن بات را هرگز در جای عمومی (چت، گیت‌هاب و...) قرار ندهید. اگر تصادفاً جایی افشا شد، از @BotFather با دستور `/revoke` توکن جدید بگیرید.

### تقویم اقتصادی
سکشن «مهم‌ترین داده‌های اقتصادی امروز» در صفحه اصلی + صفحه‌ی اختصاصی `/economic-calendar` در فرانت‌اند (نمای هفتگی، با نوار روز شامل تاریخ شمسی/میلادی و اسم روز).

**روش فعلی: وارد کردن دستی از ادمین جنگو** (چون یک API رایگان و قابل‌اعتماد برای این کار پیدا نشد؛ اغلب سرویس‌های تقویم اقتصادی پولی هستند).

نحوه‌ی کار:
1. برو به `/admin/economic_calendar/economicevent/`.
2. رویدادهای مهم هفته (مثل NFP، تصمیم نرخ بهره فدرال، CPI) را دستی اضافه کن: عنوان، کشور/ارز (مثل USD)، سطح اهمیت (High=قرمز، Medium=نارنجی، Low=زرد)، تاریخ و ساعت.
3. مقادیر «واقعی»، «پیش‌بینی» و «قبلی» را می‌توانی مستقیماً از داخل لیست (بدون باز کردن هر رویداد) ویرایش و همه را یک‌جا Save کنی — برای این‌کار در ادمین `list_editable` فعال شده.
4. چون رویدادهای واقعاً «مهم» معمولاً هفته‌ای فقط چند مورد هستند، این کار کمتر از ۵ دقیقه در هفته زمان می‌برد.

> اگر بعداً یک API رایگان و قابل‌اعتماد پیدا کردید، زیرساخت دریافت خودکار هم از قبل آماده است: کافی‌ست `ECONOMIC_CALENDAR_API_KEY` و `ECONOMIC_CALENDAR_API_BASE_URL` را در `.env` تنظیم کنید و دستور `python manage.py update_economic_calendar` را (مثلاً هر شنبه با cron) اجرا کنید. اگر این مقادیر خالی باشند (که الان همینطور است)، این دستور کاری نمی‌کند و فقط یک هشدار در لاگ می‌نویسد — کاملاً بی‌خطر است.

### مهاجرت‌های لازم
